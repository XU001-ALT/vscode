# Feature Specification: 客户演示视频生成器（Customer-Facing Demo Video Generator）

**Feature Branch**: `feat/intro-video-generator`

**Created**: 2026-10-05

**Status**: Draft

**Input**: User description: "我想利用 spec-kit 帮我剪一个关于这个项目的视频。最终生成的视频我是要面向顾客的，我希望这个视频可以展示这个项目的酷炫功能，你可以测试一下哪些问题可以得到优秀的图并剪辑进视频中。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一键产出可直接发给客户的演示视频 (Priority: P1)

负责商务或售前的人（或我本人）需要一份能直接发给客户的成品视频。他不需要任何视频剪辑技能，只需执行一次生成流程，就能拿到一段完整成片：从「用户用自然语言提问」开始，到「系统渲染出漂亮图表」结束，包含若干高光场景，画面、旁白与字幕都已就绪。

**Why this priority**: 这是本功能存在的唯一理由。哪怕只交付这一个故事，也已经能用于真实的客户沟通，因此定为 P1；其余故事都是在它之上的增强。

**Independent Test**: 在平台前后端均可正常问答的前提下，执行一次生成流程，检查输出目录是否出现一个可直接用播放器打开的成片，人工确认「能看到完整的提问到出图链路、画质清晰、无敏感信息」。

**Acceptance Scenarios**:

1. **Given** 平台前后端均在运行且问答链路可用, **When** 执行一次视频生成流程, **Then** 在约定输出目录得到一个可被播放器直接打开的完整视频文件，且全程无需人工剪辑。
2. **Given** 已生成的成片, **When** 用播放器完整观看, **Then** 片中至少存在一段「用户提出业务问题 → 界面展示图表结果」的连续画面，且画面上不出现任何密钥、连接串、真实库名或账号、内网地址。
3. **Given** 前置条件缺失（例如前端未启动、模型凭据不可用）, **When** 执行生成流程, **Then** 流程以失败状态明确报出缺失项，且不留下任何半成品视频文件。

---

### User Story 2 - 同一内容产出中英双语两版 (Priority: P2)

同一套内容需要分别产出中文版与英文版，供国内客户与海外客户各自观看，而不是只做一版加双语字幕。

**Why this priority**: 目标客户跨语言，双语是明确诉求；但单语成片已能满足 P1 的客户沟通，所以排在 P1 之后。

**Independent Test**: 用同一份内容定义分别生成中文与英文两版，逐段比对两者的分镜数量、顺序与时长，确认结构一致、仅语言不同。

**Acceptance Scenarios**:

1. **Given** 一份内容定义, **When** 分别以中文和英文各生成一次, **Then** 得到两个独立的视频文件，两者分镜数量与顺序完全一致。
2. **Given** 中文版成片, **When** 检查片中所有可见文字与旁白, **Then** 全部为中文且无英文残留；英文版同理，全部为英文且无中文残留。

---

### User Story 3 - 自动挑出「能出好图」的问答场景 (Priority: P3)

用于视频的问答场景不能随手挑：必须真的能产出好看且有说服力的可视化（趋势、对比、分布等），而不是空表、纯文本表格或报错页。生成流程需要先对一批候选提问做实测，给出可用性判定与推荐排序，只把「成功出图」的场景编入分镜。

**Why this priority**: 它直接决定成片的说服力，是「酷炫」的关键，但不影响成片能否产出；可在 P1、P2 之后迭代。

**Independent Test**: 给定一组候选提问，运行场景筛选，得到一份带判定的清单；人工抽查其中被判为「成功出图」的条目确实展示出图形可视化，被判为不可用的条目确实不是图形。

**Acceptance Scenarios**:

1. **Given** 一批候选提问, **When** 运行场景筛选, **Then** 为每个提问输出可用性判定（成功出图 / 仅表格 / 失败）与所出图表的类型，并给出推荐顺序。
2. **Given** 只采用被推荐的场景生成视频, **When** 观看成片, **Then** 视频中不出现报错提示、空白图表或纯文本表格画面。

---

### User Story 4 - 内容与产物可复现、可迭代 (Priority: P4)

产品迭代之后（界面改版、换了配色），需要能重跑一次就得到与新版本一致的新成片，而不是重新手工剪一遍；同时，已经发给客户的旧版成片必须原样留存、不被覆盖。

**Why this priority**: 它保证这套流程能长期复用，属于可持续性需求，因此排在内容质量之后。

**Independent Test**: 连续执行两次生成，确认第二次成功产出新成片，且第一次的产物文件与内容校验值保持不变。

**Acceptance Scenarios**:

1. **Given** 已存在一次历史生成的成片, **When** 再次执行生成流程, **Then** 新成片成功产出，且历史成片文件的内容与校验值保持不变。
2. **Given** 内容定义发生变更（例如替换某个分镜的提问文案）, **When** 重新生成, **Then** 成片中相应分镜随之变化，未改动的分镜保持不变。

### Edge Cases

- 前端或后端未启动、数据库不可达时，流程应立刻失败并指明是哪一项前置条件缺失，不得继续生成半成品。
- 模型凭据不可用或额度耗尽，导致某个分镜的提问无法出图时，该分镜应被替换或剔除，而不是把报错画面剪进成片。
- 某个提问返回的是纯文本表格而非图形可视化时，应被判定为「不可用」，不得进入分镜。
- 单次生成耗时超出预期（场景过多或渲染过慢）时，应有明确的上限与提示，而不是无限等待。
- 生成过程中途被中断（磁盘不足、进程被终止）时，不得留下会被误当成成品的残缺文件。
- 双语版本中某一语言的长文案溢出画面时，应被检出并提示，而不是产出文字被裁切的成片。
- 成片时长超出目标区间（例如分镜过多超出约定上限）时，应给出提示并允许裁剪。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持「一次执行产出一段完整成片」，全程无需人工剪辑。
- **FR-002**: 成片 MUST 完整呈现「用户自然语言提问 → 图表结果」的链路画面。
- **FR-003**: 成片画面 MUST 采集自真实运行中的平台界面，而非静态图片拼接。
- **FR-004**: 系统 MUST 支持用同一份内容定义，分别产出中文版与英文版两个独立视频。
- **FR-005**: 系统 MUST 先对候选提问做实测，为每个提问输出可用性判定（成功出图 / 仅表格 / 失败）与图表类型，并给出推荐顺序。
- **FR-006**: 系统 MUST 只把判定为「成功出图」的场景编入成片。
- **FR-007**: 系统 MUST 提供候选提问的可编辑入口，使用户能增删改候选提问而无需改动生成逻辑。
- **FR-008**: 内容定义 MUST 可与生成逻辑分离编辑（例如替换某个分镜的提问文案或旁白），以便非开发人员调整内容。
- **FR-009**: 成片 MUST NOT 出现密钥、连接串、真实库名或账号、内网地址等敏感信息。
- **FR-010**: 成片 MUST 为 1080p（1920×1080）及以上，帧率 30 fps 及以上，画面清晰可直接用于客户演示。
- **FR-011**: 成片 MUST 可被主流桌面播放器与浏览器直接播放，无需安装额外解码器。
- **FR-012**: 成片 MUST 包含旁白与字幕，且字幕文本 MUST 与旁白一致。
- **FR-013**: 中英两版 MUST 具有相同的分镜数量与顺序，差异仅限语言文案。
- **FR-014**: 生成流程 MUST 可重复执行；重复执行 MUST NOT 覆盖或修改历史成片。
- **FR-015**: 任一前置条件不满足时，流程 MUST 明确失败并指出缺失项，且 MUST NOT 产出残缺文件。
- **FR-016**: 成片 MUST 展示平台的核心能力，其中至少包含：以自然语言提问并得到图表结果、系统按问题自动选择合适的图表类型、界面与文案支持中英双语。[NEEDS CLARIFICATION: 「酷炫功能」的完整清单待确认——平台还具备「跨表外键自动推断」「生成失败后自动纠错重试」「手动绘图」等能力，是否也要纳入成片？]
- **FR-017**: 成片中出现的业务数据 MUST 为[NEEDS CLARIFICATION: 真实氢能实验数据，还是脱敏或示例数据？这直接决定成片能否直接对外发布]

### Key Entities *(include if feature involves data)*

- **分镜（Shot）**：成片的最小组成单元，含顺序、画面动作、该镜的旁白文案（按语言区分）与目标时长。
- **内容定义（Content Definition）**：一份可编辑的分镜集合；中英两版共用同一结构，仅文案按语言区分。
- **候选提问（Candidate Prompt）**：用于分镜的业务问题文本，附带可用性判定、所出图表类型与推荐评分。
- **成片（Produced Video）**：一次生成的产物，含语言、文件、时长、分辨率、生成时间与内容校验值。
- **语言版本（Language Variant）**：成片的语言归属，至少包含中文与英文两种。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 从执行生成到拿到可播放的成片，全程不超过 30 分钟，且人工干预次数为 0。
- **SC-002**: 产出的成片 100% 可被主流桌面播放器与浏览器直接播放，无需安装额外解码器。
- **SC-003**: 中英两版的分镜数量与顺序一致度 100%（逐段比对无差异）。
- **SC-004**: 成片中「成功出图」的画面占分镜总数比例 ≥ 80%，且出现报错画面、空白图表、纯文本表格的次数为 0。
- **SC-005**: 成片分辨率 ≥ 1920×1080，帧率 ≥ 30 fps。
- **SC-006**: 重复执行生成后，历史成片的内容校验值 100% 保持不变。
- **SC-007**: 无视频剪辑经验的需求方可在 5 分钟内独立完成一次生成。
- **SC-008**: 成片中敏感信息泄漏检出数为 0（对密钥、连接串、库名或账号、内网地址逐项核查）。

## Assumptions

- 平台前后端可在本机正常启动，问答链路可用，且服务端已配置可用的模型凭据。
- 成片面向外部客户演示，采用横屏 16:9、1080p，时长约 2–3 分钟量级（对齐仓库现有的 demo 视频）。
- 中英两版共用同一套分镜结构，仅旁白与字幕文本按语言区分。
- 成片包含旁白配音与烧录字幕；不要求真人出镜讲解。
- 生成与合成全部在本机完成，不依赖第三方云端剪辑或合成服务。
- 仓库现有的演示视频作为对照基线，新产物与其并列存放，用于替换或对照。
- 成片仅用于演示用途，不涉及生产环境部署与多用户并发。
- 依赖：可启动的前端与后端、服务端可用的模型凭据、本机具备视频编码能力。
